# KMITL Canteen

Python Desktop App สำหรับสั่งอาหารล่วงหน้า พัฒนาด้วย CustomTkinter และ SQLite

## ดาวน์โหลดแอป Demo (Windows)

[เปิดโฟลเดอร์ Demo และวิธีใช้งาน](https://github.com/69030099-Thanapon/KMITL_Canteen/tree/main/Demo) — ดาวน์โหลด ZIP แตกไฟล์ แล้วเปิด `TEST_Demo_001.exe` ได้โดยไม่ต้องติดตั้ง Python

## วิธีทำงานที่ตกลงกัน (14 ตุลาคม 2026)

- สร้าง/แก้ตาราง และเพิ่มโรงอาหาร ร้าน เมนู ราคา ตัวเลือก สถานะขาย ผ่าน **DB Browser for SQLite**
- Python ใน VS Code ใช้เชื่อมต่อ อ่านข้อมูล แสดงหน้าจอ และบันทึกออเดอร์ที่ลูกค้าสั่ง
- แอปไม่สร้างตาราง ไม่เติมข้อมูลตัวอย่าง และไม่มีหน้าจัดการเมนูอีกต่อไป
- ข้อมูลร้านและเมนูปัจจุบันเป็นข้อมูลตัวอย่าง ไม่ใช่ผลสำรวจครบมหาวิทยาลัย

## ฐานข้อมูล

เปิด `Database SQLite/canteen.db` ใน DB Browser ข้อมูลเดิมยังอยู่ ไม่ต้องสร้างใหม่

| ตาราง | ข้อมูล |
|---|---|
| canteens | โรงอาหาร |
| shops | ร้าน เชื่อมโรงอาหารด้วย canteen_id |
| menu_items | เมนู ราคา สถานะขาย เชื่อมร้านด้วย shop_id |
| menu_options | กลุ่มตัวเลือกและราคาเพิ่มของร้าน |
| orders | ผู้รับ ร้าน วันเวลารับ และสถานะออเดอร์ |
| order_items | อาหาร จำนวน ราคาและตัวเลือกขณะสั่ง |

ตาราง `app_settings` ที่อาจมีในไฟล์เดิมเป็นของขั้นนำเข้าข้อมูลรุ่นก่อน แอปไม่ได้ใช้แล้ว เก็บไว้โดยไม่ลบข้อมูลเดิม

## การตั้งค่าบนเครื่องใหม่เท่านั้น

1. สร้าง `Database SQLite/canteen.db` ด้วย DB Browser
2. เปิด `schema.sql` ในแท็บ Execute SQL แล้วรันเพื่อสร้างตาราง
3. ถ้าต้องการข้อมูลตัวอย่าง ให้รัน `sample_data.sql` เฉพาะฐานข้อมูลใหม่ที่ยังไม่มีข้อมูล
4. กด Write Changes

ไฟล์ SQL เป็นคำสั่งสำหรับเปิดใน DB Browser ไม่ใช่สิ่งที่แอปรันอัตโนมัติ ไฟล์ฐานข้อมูลจริงและ QR ส่วนตัวไม่รวมใน Git

## วิธีแก้ข้อมูล

ดูวิธีและคำสั่งใน `Database SQLite/README.md` หลังแก้ให้กด Write Changes แล้วกลับเข้าโรงอาหาร/เมนูใหม่ หรือเปิดแอปใหม่

## ความคืบหน้า 15 ตุลาคม 2026

เพิ่มปุ่ม **คำสั่งซื้อของฉัน** แสดงออเดอร์ล่าสุดก่อน พร้อมร้าน ยอด เวลารับ และสถานะ กดดูอาหาร ตัวเลือก และหมายเหตุได้ มีปุ่มรีเฟรชเพื่ออ่านสถานะล่าสุด หลังแจ้งชำระมีปุ่มติดตามออเดอร์นั้นโดยตรง

หน้านี้แสดงเฉพาะออเดอร์ของบัญชีลูกค้าที่เข้าสู่ระบบ หน้าลูกค้าอ่านข้อมูลอย่างเดียว ไม่มีปุ่มแก้สถานะ ไม่มีการเปลี่ยนตารางหรือข้อมูลตัวอย่าง

`Backend/order_history.py` อ่านประวัติและรายละเอียด ส่วน `Frontend/order_history_page.py` แสดงหน้าจอ

## สถานะระบบ

บัญชีร้านค้าเข้าสู่หน้าร้านของตัวเอง ดูรายละเอียดอาหาร ยอด ผู้รับ และเปลี่ยนสถานะ:
`awaiting_payment_review` → `paid` → `preparing` → `ready` → `completed`

ร้านสามารถตั้ง `payment_rejected` เมื่อยังตรวจรับเงินไม่ได้ และนำกลับมาตรวจใหม่ได้ การยืนยันเงินมีคำถามยืนยัน แต่ไม่ได้เชื่อมธนาคารหรือมีสลิปในระบบ ออเดอร์เก่าที่ไม่มีรหัสบัญชี/ร้านเก็บอยู่ในฐานข้อมูล แต่ไม่แสดงให้บัญชีใหม่ ไม่มีการเปลี่ยนตารางหรือเติมข้อมูลอัตโนมัติ

`Backend/shop_orders.py` อ่านออเดอร์และตรวจการเปลี่ยนสถานะ; `Frontend/shop_orders_page.py` แสดงหน้าร้าน ระบบตรวจบัญชีและรหัสร้านก่อนอ่านหรือเปลี่ยนสถานะออเดอร์ ใช้งานในเครื่องเดียว ผู้เข้าถึงไฟล์ฐานข้อมูลยังแก้ข้อมูลโดยตรงได้

เลือกโรงอาหาร ร้าน เมนู ตัวเลือก ใส่ตะกร้าแยกร้าน และกรอกผู้รับพร้อมเลือกวันเวลารับได้ แสดง QR สำหรับทดสอบและบันทึกการแจ้งชำระเป็น `awaiting_payment_review` ได้ ยังไม่ได้ตรวจเงินเข้า แนบสลิป ส่งออเดอร์ไปเครื่องร้านค้า

ราคาออเดอร์เก่าไม่เปลี่ยนตามราคาเมนูใหม่ รายการในตะกร้าที่ราคาเปลี่ยนหรืออาหารหมดต้องเลือกใหม่ก่อนยืนยัน

## ไฟล์หลัก

- `Backend/database.py`: เชื่อมฐานข้อมูลเดิมและเปิดตรวจ Foreign Key
- `Backend/catalog.py`: อ่านข้อมูลร้าน/เมนูและตรวจข้อมูลในตะกร้า
- `Backend/orders.py`: บันทึกออเดอร์และอาหารใน transaction เดียวกัน
- `Backend/menu.py`: คำนวณราคาจากข้อมูลที่อ่านมา
- `Frontend/app.py`: หน้าหลักและตะกร้า
- `Frontend/menu_page.py`: หน้าเลือกเมนู
- `Frontend/checkout_page.py`: ข้อมูลผู้รับและตรวจรายการ
- `Frontend/payment_page.py`: QR สำหรับแจ้งชำระทดสอบ

ทดสอบด้วย `python -m unittest discover -s tests -v` โดยไม่แก้ฐานข้อมูลจริง


## ระบบบัญชี

- เพิ่มโครงสร้างบัญชีครั้งเดียวตาม `Database SQLite/LOGIN_SETUP.md` ก่อนรันแอป
- สมัครลูกค้าและเข้าสู่ระบบจากหน้าแรก รหัสผ่านเก็บเป็นแฮชพร้อม salt
- ร้านค้าสร้างบัญชีจากหน้าเข้าสู่ระบบฝั่งร้านค้าได้ โดยเลือกผูกบัญชีกับร้านที่เปิดใช้งาน
- การสมัครร้านค้าในต้นแบบยังไม่มีขั้นตอนตรวจสอบว่าเป็นเจ้าของร้านจริง ก่อนใช้จริงควรเพิ่มการอนุมัติบัญชี
- คำสั่งซื้อใหม่บันทึก user_id และ shop_id ลูกค้าเห็นเฉพาะของตัวเอง ร้านเห็นเฉพาะร้านที่บัญชีผูกไว้
- ออกจากระบบแล้วล้างตะกร้าและข้อมูลหน้าจอของบัญชีเดิม
- ผู้ดูแลเครื่องสร้างบัญชีร้านด้วย `python -m Backend.create_shop_account` ไม่มีบัญชีหรือรหัสผ่านเริ่มต้น
- `Backend/users.py` จัดการบัญชีและตรวจสิทธิ์; `Frontend/login_page.py` จัดการฟอร์ม
- ยังไม่มีการรีเซ็ตรหัสผ่าน ระบบธนาคารอัตโนมัติ หรือเซิร์ฟเวอร์หลายเครื่อง


## ระบบจัดการร้านและคิวรับอาหาร (อัปเดต 2026-11-10)

- เปิดโค้ดเวอร์ชันนี้ด้วย `python main.py` หรือ `python main.py --role shop`.
- เมื่อเปิดแอปครั้งแรก ระบบเพิ่มคอลัมน์ที่ขาดและสำรองฐานข้อมูลจริงด้วย SQLite backup ไปยัง `Database SQLite/backups/` ก่อนแก้โครงสร้าง ไม่ลบออเดอร์เดิม
- ร้านเปิดรับเริ่มต้น 06:45–16:00 จำกัด 10 ออเดอร์ต่อช่วง 15 นาที (เช่น 12:00–12:14) ตั้งค่าได้จากปุ่ม **จัดการเมนู / เวลาร้าน** ในหน้าร้านค้า
- ร้านเพิ่ม/แก้เมนู ราคา รูปภาพ เปิด/ปิดขาย รูปแบบที่คิดราคาเต็ม และตัวเลือกเสริมที่บวกราคาได้ รูปที่เลือกจะถูกคัดลอกไว้ข้างฐานข้อมูลใน `menu_images/` ต้องสำรองโฟลเดอร์นี้คู่กับฐานข้อมูล
- ตรวจราคาและคิวในธุรกรรม `BEGIN IMMEDIATE` เดียวกับการบันทึก หากราคาเปลี่ยนให้ลูกค้าเลือกเมนูใหม่ คำขอเดิมจากหน้า checkout ใช้ request ID เดิม จึงไม่บันทึกซ้ำเมื่อส่งซ้ำ
- คิวที่ยังรอตรวจชำระ/ถูกปฏิเสธจะหมดอายุเมื่อเลยเวลารับ รายการที่จ่ายแล้วคงสถานะและทำเครื่องหมายเลยเวลาให้ร้านติดตาม ไม่ถือว่ารับแล้วและไม่คืนเงินอัตโนมัติ
- ตรวจเวลาทุก 30 วินาทีขณะแอปเปิด และเมื่ออ่านออเดอร์/สั่งอาหาร หลังปิดแอปทั้งหมดจะประมวลผลอีกครั้งเมื่อเปิดหรืออ่านข้อมูล ไม่มีบริการเบื้องหลังขณะปิดแอป
- ปิดรับออเดอร์ (`shops.is_active=0`) ยังให้ร้านดูแลออเดอร์เดิมได้ ระงับบัญชี (`users.is_suspended=1`) ห้ามใช้งานทั้งอ่านและแก้ไข
- สมัครร้านใหม่เป็นคำขอรออนุมัติ รวมถึงบัญชีร้านเดิมต้องตรวจสอบหนึ่งครั้ง ลูกค้าไม่สามารถอนุมัติร้านผ่านหน้าสมัครได้
- ใส่รหัสผ่านผิด 5 ครั้ง ล็อกชื่อบัญชีนั้น 5 นาที ข้อมูลการลองเข้าสู่ระบบบันทึกในฐานข้อมูล

### ผู้ดูแลอนุมัติร้าน

ใช้เฉพาะบนเครื่องของผู้ดูแลที่เชื่อถือได้ หลังยืนยันเจ้าของร้านนอกระบบแล้ว:

```powershell
python -m Backend.admin_accounts list
python -m Backend.admin_accounts approve --user-id 2 --shop-id 3
python -m Backend.admin_accounts suspend --user-id 2
python -m Backend.admin_accounts restore --user-id 2
```

เปลี่ยนเลขให้ตรงบัญชีและร้านจริง การ restore ยกเลิกการระงับเท่านั้น ไม่อนุมัติคำขอใหม่โดยอัตโนมัติ เครื่องมือผู้ดูแลนี้อาศัยสิทธิ์ผู้ดูแลเครื่อง ไม่ใช่ระบบสิทธิ์บนเซิร์ฟเวอร์ ผู้ที่เข้าถึงไฟล์ SQLite โดยตรงยังแก้ข้อมูลและสิทธิ์ได้ หากเปิดใช้งานจริงหลายเครื่องต้องแยก API/ฐานข้อมูลไว้บนเซิร์ฟเวอร์
