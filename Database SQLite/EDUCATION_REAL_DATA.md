# ข้อมูลจริงโรงอาหารคณะครุศาสตร์

แหล่งข้อมูล: รูป S__12902409.jpg, S__12902410.jpg, S__12902407.jpg และ S__12902408.jpg ที่ผู้ใช้ส่งมา ผู้ใช้ยืนยันชื่อและเมนู และยืนยันว่าราคาคู่ของครัวสิริคือธรรมดา/พิเศษ

## รายการที่ลงแล้ว

| ร้าน | จำนวนแถวใน menu_items | วิธีเก็บ |
|---|---:|---|
| ร้านครัวสิริ | 13 | ราคาธรรมดาเป็นราคาหลัก; menu_options กลุ่มขนาดมีธรรมดา +0 และพิเศษ +10 |
| ร้านแม่อุ่นเรือน | 19 | เฉพาะเมนูและราคาที่อ่านชัดและผู้ใช้รับรอง |
| ร้านพี่ฝน | 21 | แยกเมนูร้อน/เย็น/ปั่นเป็นคนละรายการตามราคา ไม่สร้างรูปแบบที่ป้ายไม่มี |
| ร้านพี่ชายข้าวราดแกง | 8 | ราด 1/2/3 อย่าง 30/40/45; กับข้าวถ้วย 20 และหมูยอ/กุนเชียง/ไข่ดาว/ไข่เจียว 10 |

ร้านพี่ชายข้าวราดแกงยังไม่มีรายชื่อกับข้าว จึงยังเลือกสั่งข้าวราดแกงไม่ได้ กับข้าวถ้วยและของเพิ่ม 5 รายการเก็บราคาไว้แต่ is_available=0 รอ UI รองรับร้านที่มีทั้งข้าวแกงและเมนูปกติ ไม่ใส่กับข้าวสมมติแทนร้านจริง

ข้อมูลที่ยังรอ: ราคาอาหารตามสั่งร้านพี่ชายแยกตามวัตถุดิบ, รายชื่อกับข้าว, เมนูส่วนที่อ่านไม่ชัดของแม่อุ่นเรือน, ราคาผลไม้แต่ละชนิด, โปสเตอร์เครื่องดื่มด้านล่าง, และการกำหนดว่าโยเกิร์ต/วิปครีม +15 ใช้กับเมนูใดได้บ้าง

## วิธีอัปเดต

- ไฟล์ 02_shop_visibility.sql เพิ่ม shops.is_active บนฐานข้อมูลเดิม รันครั้งเดียวเท่านั้น
- ไฟล์ schema.sql สำหรับเครื่องใหม่มี is_active แล้ว ไม่ต้องรัน 02 ซ้ำ
- ไฟล์ 03_education_real_shops.sql เพิ่มร้านและเมนูโดยค้นรหัสจริงจากชื่อ ไม่เดารหัสร้าน รันซ้ำไม่สร้างเมนูซ้ำ
- ร้านตัวอย่างเดิม 3 ร้านของครุศาสตร์ตั้ง is_active=0 ส่วนบัญชี ออเดอร์ และรายการอาหารเดิมเก็บอยู่ครบ
- Backend/catalog.py อ่านเฉพาะร้าน is_active=1 สำหรับหน้าลูกค้าและตรวจตะกร้า
- การนำเข้าครั้งนี้ทำใน transaction เดียว ตรวจ Foreign Key และเทียบข้อมูล orders/order_items/users ก่อนบันทึก

เปิด DB Browser แล้วกดอ่านฐานข้อมูลใหม่หากยังแสดงโครงสร้างก่อนแก้ ไม่ต้องรันไฟล์นำเข้าอีก เพราะลงข้อมูลจริงแล้ว

## SQL สำหรับดูผล

```sql
SELECT shops.shop_id, shops.name, shops.shop_type, shops.is_active
FROM shops JOIN canteens USING(canteen_id)
WHERE canteens.name = 'คณะครุศาสตร์';

SELECT shops.name AS shop, menu_items.name AS menu, price, is_available, menu_type
FROM menu_items JOIN shops USING(shop_id) JOIN canteens USING(canteen_id)
WHERE canteens.name = 'คณะครุศาสตร์' AND shops.is_active = 1
ORDER BY shops.shop_id, menu_items.menu_id;
```


## ปรับตัวเลือกเครื่องดื่มและร้านพี่ชาย 9 พฤศจิกายน 2026
- รัน `04_drink_variants.sql` หลัง `03_education_real_shops.sql` ใน Execute SQL แล้ว Write Changes หากปุ่มยังเปิดอยู่
- ตาราง `menu_items` เก็บชื่อเครื่องดื่มหลัก 8 ชื่อ; `menu_variants` เก็บรูปแบบและราคาเต็มของแต่ละเมนู เชื่อมด้วย `menu_id`
- เปลี่ยนราคาที่ `menu_variants.price` ได้โดยตรง แอปใช้ราคาต่ำสุดที่พร้อมขายเป็นราคาเริ่มต้น
- `menu_variants.is_available=0` ซ่อนเฉพาะรูปแบบนั้น ถ้าหมดทุกแบบ เมนูจะไม่แสดง
- เอสเพรสโซ่ 35/40/45, ลาเต้และคาปูชิโน 35/45/50, ชานม ชาเขียว โกโก้ 35/35/40 (ร้อน/เย็น/ปั่น)
- ช็อกโกแลตลาเต้ เย็น45/ปั่น50; นมสดโอริโอ้ ปั่น40 ไม่มีรูปแบบร้อนที่ไม่ได้ระบุบนป้าย
- เมนูเครื่องดื่มชื่อเดิมที่ต่อท้ายรูปแบบถูกปิดขาย เก็บประวัติออเดอร์และบัญชีเดิมครบ
- ไม่เพิ่มอเมริกาโน่หรือน้ำผลไม้ที่ยังไม่ทราบราคาจริง
- เปิดหมูยอ กุนเชียง ไข่ดาว ไข่เจียว 10 บาทเป็นเมนูแยก ร้านเดียวแสดงเมนูแยกกับข้าวราดแกงร่วมกันได้
- `05_phee_chai_menus.sql` เพิ่มข้าวกะเพรา50 และข้าวผัด45 โดยใช้ราคาของร้านอาหารตามสั่งเดิมตามคำขอ ยังไม่ใช่ราคาที่ตรวจสอบจากร้านพี่ชาย
- ยังต้องระบุชื่อกับข้าวสำหรับราดแกง และราคาเมนูอื่นแยกตามวัตถุดิบก่อนเปิดขาย
- ฐานข้อมูลจริงได้รัน04และ05แล้ว ไม่ต้องรันซ้ำเพื่อเปิดแอป

ดูตัวเลือกและราคาใน DB Browser:
```sql
SELECT shops.name AS shop, menu_items.name AS menu,
       menu_variants.name AS variant, menu_variants.price,
       menu_variants.is_available
FROM menu_variants
JOIN menu_items USING(menu_id)
JOIN shops USING(shop_id)
ORDER BY shops.shop_id, menu_items.menu_id, menu_variants.variant_id;
```


## ตัวเลือกเส้นและทดสอบสองหน้าต่าง
- รัน `06_noodle_options.sql` หลังไฟล์ก่อนหน้า; ฐานข้อมูลเครื่องนี้รันแล้วและสำรองไว้ใน outputs/backups
- `menu_item_options` ผูกตัวเลือกกับ `menu_id` จึงมีตัวเลือกเส้นเฉพาะเมนูก๋วยเตี๋ยว ส่วนเมนูข้าวในร้านเดียวกันไม่มีตัวเลือกเส้น
- คงเส้นเล็ก เส้นใหญ่ เส้นหมี่ บะหมี่ และน้ำ/แห้งจากระบบเดิมตามคำขอ ต้องยืนยันความพร้อมขายกับร้านจริงอีกครั้ง
- เมนูบะหมี่–เกี๊ยวคงเส้นตามชื่อ เลือกน้ำ/แห้งได้ ขนาดธรรมดา/พิเศษยังใช้ราคาจากป้าย
- หน้าเข้าสู่ระบบเลือกฝั่งลูกค้าหรือร้านค้า บัญชีต้องตรงกับฝั่งที่เลือก ไม่ได้ให้ลูกค้าเข้าจัดการร้านโดยไม่เข้าสู่ระบบ
- ปุ่มเปิดหน้าต่างร้านค้า/ลูกค้าเปิดอีก process จึงมี session แยกกัน แต่ใช้ canteen.db เดียวกัน
- หน้ารายการและรายละเอียดออเดอร์ตรวจการเปลี่ยนแปลงฐานข้อมูลทุก3วินาที แล้วอ่านใหม่เมื่อมีการเปลี่ยนแปลง ไม่ใช่การตรวจเงินจากธนาคารอัตโนมัติ
- ใช้บนคอมพิวเตอร์เดียวกันก่อน การใช้ต่างเครื่องยังต้องออกแบบฐานข้อมูลหรือ API ส่วนกลาง
- บัญชีร้านค้าเดิมยังอยู่กับร้านตัวอย่าง ต้องสร้างบัญชีร้านจริงผ่าน `python -m Backend.create_shop_account` แล้วเลือกร้านจริงและตั้งรหัสผ่านเอง
- เปิดลูกค้า: `python main.py --role customer`; เปิดร้านค้า: `python main.py --role shop`
